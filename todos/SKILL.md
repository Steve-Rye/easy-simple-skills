# todos

直接通过文件系统操作项目 `todo/` 下的 Markdown 任务文件；文件位置决定状态，文件名决定父子关系。

## 基本规则

- 一个 Markdown 文件对应一个任务；任务内容必须清晰且无歧义。
- 任务文件是与用户的默认沟通基线；与最新验证事实冲突时，以最新事实为准并在与用户的沟通中说明。
- 只有用户明确要求“任务进度更新”或“更新任务”时，才将进展、偏差和下一步写回任务文件。
- 用户明确调整待办规则时，先更新本 skill 再处理任务。

## 目录与状态

```text
todo/
  pending/
  done/
  abandon/
```

- 新建任务放入 `pending/`；完成、放弃时分别移入 `done/`、`abandon/`。
- 任务状态只由 `pending/`、`done/`、`abandon/` 中的位置决定。
- 状态变更在同一 `todo/` 根目录内完成，除非用户明确要求迁移。外部计划或设计文档不自动等同于 todo 任务。

## 文档命名示例

- 命名示例：`step01.01_任务简短名称.md` 或 `step001.001_任务简短名称.md` 或 `step01.02_任务简短名称.md`等。命名中的编号代表任务执行顺序，序号可多层级，按照当前工作空间的命名习惯即可。

## 操作

- 查看：检查三个状态目录，按状态归纳总体项目任务进度。
- 创建：确认项目根目录以及 `todo/` 文件夹；不明确项目根目录或缺少 `todo/` 文件夹或遇到歧义时，与用户沟通清楚后再将任务写入 `pending/`，并说明创建结果。
- 更新：仅在用户明确要求时，依据最新事实更新相关任务，保持状态不变，除非用户确认更新任务状态。
- 完成：用户明确确认，或父任务满足自动完成条件时，移入 `done/`；完成子任务后检查父任务。
- 放弃：用户明确确认任务失效或不再继续时，移入 `abandon/`；放弃子任务后说明对父任务的影响。
