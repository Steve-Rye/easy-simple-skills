# 公开发布 implement Skill

## 背景与动机
`easy-simple-skills` 已公开 `clarifier` 与 `todos`，但尚未收录用于严格落地交付的 `implement`。现有本地版 `implement` 依赖同级 Skill、`todo/` 目录约定和 Python 校验器，公开仓库尚未说明这些协作关系、安装方式、许可证及本地验证方法；`todos` 也未定义 `todo/reviews/` 审查产物目录。

## 最终目标
将 `implement` 及其审查摘要校验器加入本仓库，形成一套以中文文档为主、遵循开放 Agent Skills 格式、可由支持该格式的代理安装和显式调用的三 Skill 工作流。仓库采用 MIT；发布前可在本地完成确定性的结构校验和 Python 单元测试，不引入 GitHub Actions、模型评测或需要密钥的服务。

## 基本假设
- `clarifier`、`todos` 与 `implement` 以本仓库同级目录共同分发；使用者可整体安装，也可明确了解缺少协作 Skill 时的限制。
- 任务文档中明确列出的实施、测试和验证命令构成执行授权；仍受运行环境和宿主代理的强制权限策略约束。
- `implement` 同时适用于软件开发、个人项目和科研/数据分析任务；科研结论不支持原假设不等同于实现或验证失败，原始数据不得为迎合结论而被覆盖或篡改。
- 跨代理兼容以开放 Agent Skills 结构和无平台专有主流程为目标，不承诺不同代理对自然语言隐式触发的完全一致行为。

## 实施边界以及实施细节

TL;DR：新增 `implement/`，把严格实施流程、审查摘要和科研真实性规则公开化；统一三个 Skill 的元数据和目录契约，并以 README 与本地测试保证可安装、可理解、可验证。

- 新增 `implement/SKILL.md`，`name` 必须为 `implement` 且与目录名一致；前置元数据声明 MIT、兼容性和中文触发条件。仅在用户使用“开始实施”或显式调用 Skill 时启动完整流程；在缺少可执行任务文档时，要求用户指定文档，并委托同级 `clarifier` 完成澄清。
- 保留“审阅文档、落盘实施、快速验证、脚本使用说明、风险分级的完整环境验证、审查摘要、结果确认和状态处理”的流程。低风险任务默认执行快速验证；任务文档明确要求完整环境验证、或变更涉及部署、生产数据、不可逆写入、费用或安全边界时执行完整验证。任务文档列出的命令视为授权；未列出的高影响命令必须在运行前取得用户明确同意。
- 将科研/数据分析真实性规则保留为 `implement` 的适用分支，明确其只适用于涉及研究结论、数据处理或原始数据的任务；普通开发任务按通用验证规则执行。
- 新增 `implement/scripts/check_review_brief.py`，只依赖 Python 3 标准库，校验审查摘要的标题、恰好三个二级章节、前两个章节的 200 可见字符上限、“本次任务做了什么”为列表，以及无交付偏差时使用 `- 无`。脚本头部必须说明用途、输入、输出、依赖和可直接运行的示例命令。
- 新增校验器的标准库单元测试，至少覆盖：合规摘要、章节顺序错误、字符超限、成果非列表和“无偏差”格式错误；测试不可依赖网络、模型或外部服务。
- 更新 `todos/SKILL.md`：明确 `todo/pending/`、`todo/done/`、`todo/abandon/` 仍是任务状态目录；`todo/reviews/` 是由 `implement` 写入的非任务状态审查摘要目录，文件名须与原任务文件一致，不能据此推断任务状态。
- 更新 `clarifier/SKILL.md` 与 `todos/SKILL.md` 的开放格式元数据、兼容性与同仓库协作说明；不得把 Codex 或 Claude Code 的私有前置字段写入三项 Skill 的主流程。
- 更新根目录 `README.md`：列出三个 Skill、协作顺序、目录结构、`todo/` 和 `reviews/` 约定、前置条件与本地验证命令；提供支持开放格式的通用安装说明，并分别给出 Codex 的 `$implement` 和 Claude Code 的 `/implement` 显式调用示例。README 为简体中文。
- 在仓库根目录新增 MIT `LICENSE`。不新增 GitHub Actions、CI 配置、远程模型评测、插件清单或网络依赖。

## 可接受的风险
- 不同代理对 YAML 扩展元数据、相对链接和自然语言触发的支持程度不同；首版只保证开放格式与显式调用说明，不进行跨平台代理实测。
- 任务文档被视为命令授权会扩大自动执行范围；用户必须审阅任务文档，宿主环境的权限限制仍优先。
- 本地静态检查和脚本单测不能证明代理在真实复杂项目中的推理质量；后续可根据真实使用反馈补充提示场景评测。

## 验收标准
- 仓库根目录包含 `clarifier/`、`todos/`、`implement/`、`README.md`、`LICENSE` 与本任务新增的本地测试文件；三个 `SKILL.md` 均有有效 YAML 前置元数据，`name` 与所在目录名一致，且不含平台私有的必需字段。
- `implement/SKILL.md` 明确：显式触发方式、任务文档缺失时的处理、与 `clarifier`/`todos` 的协作、风险分级验证、审查摘要路径、科研数据真实性规则及任务状态处理边界。
- `todos/SKILL.md` 明确 `todo/reviews/` 不决定任务状态，且 `implement` 可据同一 `todo/` 根目录中的原任务生成同名审查摘要。
- `README.md` 为简体中文，含三个 Skill 的作用、目录结构、通用安装说明、Codex 与 Claude Code 的显式调用示例、Python 3 前置条件和所有本地验证命令；`LICENSE` 为完整 MIT 文本。
- 在仓库根目录运行 `python3 -m unittest discover -s implement/tests -p 'test_*.py'` 通过；测试覆盖校验器列出的五类场景，且无需网络或密钥。
- 在仓库根目录运行脚本说明中列出的合规审查摘要示例命令成功；对至少一个结构不合规的 fixture 运行该脚本以非零状态退出。
- 使用当前环境可用的开放 Agent Skills 结构校验工具校验三个 Skill；若工具未安装，记录缺失原因并以本地标准库测试验证目录名、必要前置元数据和相对文件引用。
- 不创建 `.github/workflows/` 或其他 CI 配置。
